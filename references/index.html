References

These are the books, tools and posts this site leans on. Read them when you want the full story behind a page here. Each entry says what it is best for and which pages it backs.

Books and courses

The books behind the trade-offs

  • Designing Data-Intensive Applications, 2nd edition, Martin Kleppmann and Chris Riccomini, O'Reilly, 2026. dataintensive.net Best for learning replication, partitioning, transactions and consistency as trade-offs instead of recipes. Backs Home, Staff Path and Cloud.
  • Database Internals, Alex Petrov, O'Reilly, 2019. goodreads.com Best for the implementation underneath this site: B-tree and log-structured storage, page cache, write-ahead log, and how clusters reach consistency. Backs Home, PostgreSQL, MySQL, MongoDB and Staff Path.
  • Use The Index, Luke, Markus Winand. use-the-index-luke.com Best for the fastest way to stop writing slow queries: B-trees from the leaf nodes up, then how the WHERE clause, joins and sorting use an index or fail to. Backs Reference, PostgreSQL, MySQL and Cheat Sheet.
  • PostgreSQL 14 Internals, Egor Rogov, Postgres Pro, 2023, free PDF. postgrespro.com Best for how Postgres actually works: MVCC, buffer cache, WAL, locking, the planner, and every index type. Backs PostgreSQL and Reference.
  • The Art of PostgreSQL, 2nd edition, Dimitri Fontaine, 2026 update. theartofpostgresql.com Best for writing SQL that does the work instead of thousands of lines of application code, with real datasets to run it against. Backs PostgreSQL and Reference.
  • Building with Patterns, Daniel Coupal and Ken W. Alger, MongoDB blog. mongodb.com Best for MongoDB schema design before you build: twelve patterns, each with its trade-off stated. Backs MongoDB and Staff Path.
Tools and posts

The tools and posts behind the checks

  • explain.depesz.com, Hubert Lubaczewski. explain.depesz.com Best for reading a Postgres plan line by line in a readable layout instead of raw text. Backs Reference and PostgreSQL.
  • pgMustard. pgmustard.com Best for pasting in a Postgres plan and getting the slow lines flagged with the fix beside each one. Backs Reference and PostgreSQL.
  • MySQL 8.0 Reference Manual: InnoDB Architecture (Figure 17.1). dev.mysql.com Best for seeing the InnoDB layout in one picture: buffer pool, redo log, undo, and how they connect. Backs MySQL.
  • MySQL Internals: Pages, B+Trees, Indexes, the Optimizer, WAL, Binlog and Replication, Amar. blog.amarkhamkar.com Best for a single walk through MySQL internals from pages and B+ trees to the optimizer, WAL, binlog and replication. Backs MySQL and Staff Path.
  • Data Structure Simulators: B-Tree, B+Tree, Quad-Tree, R-Tree. simulation.amarkhamkar.com Best for watching a tree grow, split and rebalance instead of picturing it from a diagram. Backs Home, Staff Path and Cheat Sheet.

The one invariant: COMMIT means the log record is on disk. pg_wal in PostgreSQL, ib_logfile0 + mysql-bin in MySQL, journal/WiredTigerLog + the oplog in MongoDB. The data files (base/…, *.ibd, collection-*.wt) are where checkpoints place the result afterwards, on their own schedule. Every guarantee on this page, durability, replication, point-in-time recovery, is a consequence of that ordering, and every number on this page is checkable with the commands given beside it.

PostgreSQL, MySQL/InnoDB, and MongoDB/WiredTiger internals, from physical layout to production failure modes. File names, paths, thresholds, and commands are the production ones.
