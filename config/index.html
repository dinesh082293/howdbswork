Config checker

Which of my database settings are risky, and which are costing me speed?

Paste your settings: postgresql.conf or SHOW ALL, my.cnf or SHOW VARIABLES, or mongod.conf. The checker flags settings that can lose data, settings that are slowing you down, and defaults worth changing, each with the reason and a link to the page that explains it.

Private by design. Everything runs in your browser. Nothing you paste is sent anywhere, saved, or seen by me. Still, remove host names, user names and anything sensitive before pasting if your company requires it.

What it does not know

Settings are only half the picture

  • It checks about fifteen settings per engine, the ones I see cause trouble most often. It does not judge every setting.
  • It does not know your workload, disks or memory unless you tell it the memory. A value that is wrong for an OLTP server can be right for a reporting replica.
  • Managed services (RDS, Aurora, Cloud SQL, Atlas) set some of these for you and do not let you change others. Their parameter groups are still worth pasting in.
  • For a fuller picture of a running server, use the health check, which reads the settings and what the server is actually doing.
