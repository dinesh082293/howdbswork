For AI assistants

Use this site from your AI assistant

Can Claude or Cursor answer from these design docs instead of from memory?

Yes. The site comes with a small MCP server. Add it to your assistant and, when you ask which database an application needs, how big it will get, or why a replica lags, the assistant looks the answer up here and gives you the link. It runs on your own machine, has no dependencies, and sends nothing anywhere.

What it can do

Four tools

ToolWhat you askWhat comes back
recommend_store"Which database for ticket sales with seat selection?"The matching design doc: what goes where and why, what breaks first, and the link.
get_design"Show me the payments design."One design doc in full: workload, placement, failures, where to run it.
estimate"10 million documents, 8 chunks each, 1,536 dimensions: how much memory?"The same numbers as the Estimate it sliders, with a link that opens them on the page.
find_lesson"Why does vacuum not clean up dead rows?"The lessons that explain it, with one-line summaries.
Set it up

Two minutes, Node 18 or newer

Get the code once:

git clone https://github.com/dinesh082293/howdbswork.git

Claude Code:

claude mcp add howdbswork -- node /path/to/howdbswork/mcp/server.mjs

Claude Desktop (claude_desktop_config.json) or Cursor (.cursor/mcp.json):

{
  "mcpServers": {
    "howdbswork": {
      "command": "node",
      "args": ["/path/to/howdbswork/mcp/server.mjs"]
    }
  }
}

Then ask your assistant a design question. A git pull picks up new design docs and lessons.

How it works

The same pages, read by a program

  • A build script reads the design docs and lessons from this site into one file, so the server answers in the same words as the pages.
  • The estimates run the same formulas as the Estimate it sliders, from the same file. Numbers measured in the lab notebooks are labelled as measured; the rest are labelled as assumptions.
  • It matches your question to a design doc by the words in it. It is a lookup, not a model, so it will point you to the nearest doc rather than invent one.
  • For assistants that read the web instead, the site also has an llms.txt: a plain list of every page with a one-line summary.

Building agents yourself? The agent memory design doc covers where their state, logs and memories go.

The one invariant: COMMIT means the log record is on disk. pg_wal in PostgreSQL, #innodb_redo/#ib_redo0 + mysql-bin in MySQL, journal/WiredTigerLog + the oplog in MongoDB. The data files (base/…, *.ibd, collection-*.wt) are where checkpoints place the result afterwards, on their own schedule. Every guarantee on this page, durability, replication, point-in-time recovery, is a consequence of that ordering, and every number on this page is checkable with the commands given beside it.

PostgreSQL, MySQL/InnoDB, and MongoDB/WiredTiger internals, from physical layout to production failure modes. File names, paths, thresholds, and commands are the production ones.
