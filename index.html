Three engines, one job

Where the bytes sit decides how it behaves

The number that runs this pageOne lookup in a 10-million-row table takes 0.05 ms with the right index, or 3 to 8 seconds without one. Same data, same hardware, same query. The difference is entirely physical: which pages get read, and how many.

PostgreSQL

Best when correctness matters most.

One data directory. Each table and each index is its own file of 8 KB pages. Updates write a brand-new row version; VACUUM cleans the old ones.

Log: WAL in pg_wal/ · Data: base/<db>/<file> · Memory: shared_buffers

PostgreSQL, in one line →

MySQL · InnoDB

Best for fast websites where most lookups are by ID.

Each table is one .ibd file that is the primary-key index. Rows are stored in ID order, 16 KB pages. Two logs: redo for crashes, binlog for copies.

Logs: #innodb_redo/#ib_redo0 + mysql-bin.* · Data: shop/users.ibd · Memory: buffer pool

MySQL · InnoDB →

MongoDB · WiredTiger

Best when every record looks a bit different.

Documents instead of rows. Each collection and index is its own compressed .wt file. Copies follow the oplog, a special collection in the local database.

Logs: journal/WiredTigerLog.* + local.oplog.rs · Data: collection-*.wt · Memory: WiredTiger cache
