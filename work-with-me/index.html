Work with me

Can you look at my database?

I am a database engineer with more than nine years of running MySQL and PostgreSQL in production, on-premises and on AWS, including high availability with Patroni, etcd, InnoDB Cluster and Group Replication. This site is how I explain the work. If you would rather have me look at your own system, this page says how.

The health check

A written review of one database, ranked by risk and by cost

I read the same things this site teaches you to read, on your system, and write down what I find, in order of what to fix first.

Durability and recovery

  1. Commit and replication settings, against what a lost write costs you
  2. Backups and point-in-time recovery, and whether a restore has been tested
  3. Failover: how it is triggered, and how long it takes

Performance

  1. The top queries by total time, with their plans
  2. Missing and unused indexes
  3. Bloat, vacuum or purge backlog, cache hit ratio, connection use

Cost

  1. Instance and storage size against the measured load
  2. Replicas, I/O, backups and non-production copies
  3. A safe order for cutting, as on the cost page

I work with PostgreSQL and MySQL, self-managed or on AWS, including Aurora and RDS.

The agents review

Is your database ready for AI agents?

Agents use a database differently from people: they write their own queries, open many connections at once, and need memory that is fast, filtered by tenant, and forgettable. I review the database side of an agent system before it reaches production, or after it starts hurting.

Safe access

  1. Roles the agent uses: read-only where it can be, and no access to columns it should not see
  2. Statement timeouts, row limits, and a replica for agent queries
  3. Masking of sensitive columns in the database itself, with views, column privileges or row-level security

Memory and retrieval

  1. Where conversations, checkpoints, tool calls and long-term memories live, as in the agent memory design doc
  2. Vector index sizing, recall and filtered search, measured on your data
  3. Forgetting: retention, deletion on request, and embedding model changes

Load

  1. Connections from parallel runs, and pooling
  2. The queries agents actually send, ranked by cost
  3. What happens when ten times as many runs start at once

You get a written report ranked by risk, the same shape as the health check. PostgreSQL with pgvector is where I go deepest; I also review MySQL and Redis in agent systems.
