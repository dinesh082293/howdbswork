Corrections · what I got wrong, and when I fixed it

Corrections

What on this site was wrong, and what does it say now?

I check the site against the documentation for PostgreSQL 18, MySQL 8.4 and MongoDB 8.0, and every command on the engine pages runs against real servers in CI. Some mistakes still get through. When I fix one that changes what a page teaches, it goes here, with the date. Typos and wording changes do not get a line. Found something wrong? Select the sentence on any page and press Suggest a fix, or use the link at the bottom of every page. It opens a GitHub issue with the page and the quote already filled in.

DateWhereWhat it saidWhat it says now
Nov 19, 2026Notebook 7The text said a ZINCRBY round trip took 0.07 ms and the Cassandra partition read took 2.4 ms, while the transcript shown came from a later run.The text now quotes the transcript: 0.08 ms and 3.3 ms. The conclusions did not change.
Nov 18, 2026Notebooks 1, 2 and 3The text quoted timings from the first run (for example 0.29 ms per durable commit in PostgreSQL, a 75 ms scan), while the transcripts on the page came from a later run.The text now quotes the transcripts shown: 0.24 ms, 0.57 ms and 0.95 ms per durable commit, a 70.5 ms PostgreSQL scan, a 509 ms MySQL scan, a 436 ms MongoDB scan, and a starting table size of 5.6 MB. The conclusions did not change.
Nov 17, 2026MVCC lab, Staff PathThe lab showed the snapshot being taken at BEGIN.In PostgreSQL at Repeatable Read, and in InnoDB, the snapshot is taken at the first query in the transaction, not at BEGIN. I rewrote the lab, added an isolation level switch and a Reset button, and the log now says when the snapshot is taken.
Nov 17, 2026Transaction ID wraparound, Staff PathThe ladder of thresholds was incomplete.The ladder now reads: autovacuum_freeze_max_age (200 million by default) forces an anti-wraparound vacuum, vacuum_failsafe_age (1.6 billion) turns on the failsafe, and the server refuses new transaction IDs as it nears about 2.1 billion.
Nov 17, 2026Checkpoint spacing, Staff PathCheckpoint spacing was described as a fixed interval.It is set by checkpoint_timeout and max_wal_size, whichever comes first, and max_wal_size is a soft limit.
Nov 17, 2026synchronous_commit, Staff Path and Start hereoff and local were described as the same thing.They are different. off does not wait for the local WAL flush. local waits for the local flush but not for any standby.
Nov 17, 2026MySQL 8.4 defaults, MySQL page and homeThe pages assumed older defaults.In MySQL 8.4, innodb_adaptive_hash_index is OFF and innodb_change_buffering is none by default. The doublewrite buffer lives in #ib_*.dblwr files since 8.0.20, not in ibdata1.
Nov 17, 2026MongoDB sorts, MongoDB page and ReferenceA sort over 100 MB was described as failing.Since MongoDB 6.0, a blocking sort over 100 MB spills to disk by default.
Nov 17, 2026MongoDB journal, MongoDB pageThe page mentioned storage.journal.enabled as a setting.The option was removed in MongoDB 6.1. Journaling is always on.
Nov 17, 2026Sample output, Staff PathSome outputs looked like captured runs but were written by hand.Every hand-written output now says "sample output". Captured runs say where and when they ran, as on the Decisions and Notebooks pages.
